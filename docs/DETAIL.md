# 对话模式

侧边栏顶部那一行的最右边（搜索 / 视图选项 / 新建对话三个按钮的右侧）多一个两段式开关（`对话` / `写代码`），处于同一行、同一行高。切到「对话」会直接打开一个只用来聊天的会话：不用选目录、没有文件与 shell 工具、可以联网搜索，system prompt 可以在设置里改。

## 它解决什么

DSH 默认是一个编码工作台：新建会话要绑一个工作区目录，Agent 一上手就能读文件、跑命令、改代码。可很多时候只想问点事、查点资料。这个插件把那种「打开就能说」的状态做成一个开关，而不是另一套应用。

## 怎么用

1. 侧边栏顶部、折叠按钮左边的开关里点聊天图标：进入对话模式。
2. 直接输入问题。需要最新信息时会自己检索网页并在回答里给链接。
3. 想回到编码：点 `</>` 图标，回到最近一个不是「对话」的工作区，开一个正常的编码会话。
4. 改 system prompt：**设置 → 对话模式**，改完保存；下一条消息就按新提示词回答，已开的对话不用重开。

开关的当前状态由「正在显示的会话属于哪个工作区」决定，所以从侧边栏点开一个编码会话时，开关会自己跳回 `</>`。

## 对话模式里有什么

会话由本插件声明并安装的 `chat` Agent 预设组合而成，能力集合写在 `cordis.patch.yml` 的 `preset-chat` 行里：

| 能力 | 说明 |
|---|---|
| 人设 | `@deepseek-ai/dsh-persona` 的一段对话人设 |
| 联网 | `@deepseek-ai/dsh-tool-web`：`web_search`、`web_fetch` |
| 提问 | `@deepseek-ai/dsh-tool-ask-user`：需要你拍板时弹选择 |
| 压缩 | `compaction` 组：长对话会自动压缩历史、裁剪工具结果 |
| 时间 | `@deepseek-ai/dsh-time-context`：把当前时间当运行时上下文 |

预设本身没有 `tool-bash`、`tool-fs`、`tool-fs-search`、`tool-todo`、`tool-subagent` 等任何写文件或跑命令的能力。预设管不到「整个部署注册的全局工具」（MCP 服务器、工作目录切换等），所以 Host 端还会给每个对话会话加一道工具屏蔽：只保留 `web_search`、`web_fetch`、`ask_user_question`。实测一个新建对话会话的请求里只剩这三个工具。

它收到的提示词也要求它不要假装执行过没有的工具；真要改代码时提醒你切回「写代码」。

## 两个模式互相隔离

侧边栏跟着模式走：对话模式下隐藏所有工作区行和所有非对话会话，只剩一条条对话记录，连「对话」这个目录也不出现；写代码模式下反过来隐藏「对话」工作区和它下面的会话。两边的会话永远不会混在一起。

宿主的会话列表没有提供过滤插槽，所以过滤是一张由插件生成的样式表，作用在宿主自己的 `data-row-key` 行上（`workspace:<id>` / `session:<id>`）：不改宿主 DOM，新建会话后自动重算。对话模式的列表要"显示全部"：宿主对每个工作区只渲染前几条，其余藏在一个「展开其余 N 个会话」按钮后面（那次截图里只看到 5 条就是它）。插件在对话模式下会读那个按钮的 `aria-expanded`，是 `false` 就替用户点一次（最多重试 4 次），展开后按钮保持 `true` 不会来回切；按钮本身仍隐藏，列表看起来就是完整的一列。

对话模式下这些行还去掉了层级缩进和前导状态格（`padding-left:8px`、隐藏 16px 的 slot），标题与上方「新会话」行左对齐，不会平白空出一段。同一张样式表还把侧边栏顶部那段标题「工作区」换成「对话」，并把「添加工作区」按钮的图标换成「新建对话」气泡（用 mask 换字形），点击由插件用捕获阶段的监听拦下来，改成新建一个对话；写代码模式下标题、图标、无障碍名称和宿主原有行为都会恢复。输入框那一行也顺手清掉了两个只在写代码时有意义的控件：沙箱/权限预设（`conversation.input.permission`）和第三方模式选择器（`data-omo-mode-root`，本机装的是 OMO 的 Sisyphus）。新对话的输入框上方那行「工作区 / 模式」选择器（`heroWorkspaceRow` 里的 📁 与预设芯片）也一起隐藏——对话永远在对话工作区、用 `chat` 预设，没什么可选。

## 工作区

对话会话放在插件自己准备的工作区里，默认目录是 `~/DSH-Chat`（可在插件配置的 `workspaceDir` 改），侧边栏名字是「对话」（`workspaceTitle`）。插件加载时创建目录并登记工作区，所以用户永远不需要选目录。

## 引用与来源

宿主的正文用 Markdown 渲染，孤零零的 `[4]` 只是普通文字，点不开。所以默认提示词要求模型用带方括号编号的链接：正文写 `[[1]](https://…)`（渲染出来就是可点的 `[1]` + 站点图标），并在回答末尾加「来源」小节逐条列编号、标题、链接。实测一次联网回答：正文里的 `[1]` / `[2]` 都是可点链接，末尾「来源」列出了两条带链接的条目。

渲染样式参考网页版：正文里这类链接会被插件改成**上标小圆圈**——15×15 圆形浅底、9px 编号、不显示链接图标、整体上移 2px，点一下仍然打开来源。实现只给那个链接加一个 class 和一个 `data-dpc-cite` 属性，CSS 用伪元素画编号，链接本身（href、点击行为）不动；回答流式输出时用一个 `MutationObserver`（按帧合并）重新打标，所以边流边出也是这个样式。

鼠标停在徽章上会弹出**来源卡片**（站点、标题、摘要、链接），数据不是我重新抓的：插件读取当前会话自己的 `tool/result` 事件里的 `meta.sources`（`web_search` 返回的 url/title/snippet），按被引用 URL 匹配。被引用的是 `web_fetch` 抓回来的页面时没有摘要，就退回用回答里「来源」列表那张链接的标题文字；连标题也拿不到就显示 URL。日期字段官方结果里没有，所以卡片不显示日期（摘要里若带日期会自然出现）。

限制：这是提示词 + 样式层面的做法，没有改宿主的 Markdown 渲染器；已经存在的旧对话里那些**没有链接**的裸 `[4]` 不会变（只有 `[[n]](url)` 渲染出来的链接会被改成徽章）。

## 配置

| 字段 | 默认 | 作用 |
|---|---|---|
| `systemPrompt` | 内置中文提示词 | 初始默认值，也是「恢复默认」的目标；设置页保存过的值优先 |
| `workspaceDir` | `~/DSH-Chat` | 对话会话所在目录 |
| `workspaceTitle` | `对话` | 侧边栏里这个工作区的名字 |

提示词保存在 `$DSH_HOME/dsh-plugin-chat.json`（默认 `~/.dsh/dsh-plugin-chat.json`，权限 0600）里，不是 Loader 配置，所以保存后不需要重启插件，也不会打断正在进行的对话。写不进去时设置页会直接报错，而不是假装保存成功。

这一行也是宿主私有的（没有插槽），所以开关画在 frame 级浮层（`shell.overlay`）里，位置按实测的会话区标题行几何算出来：右边缘贴该行右侧 12px、垂直居中；同时用一条 `margin-right:70px` 把这三个按钮往左压，腾出开关的位置。开关本身不画"填充容器"——固定的底色在侧边栏行上会显得像一块对不上的黑方块，所以只有选中的那一段用宿主自己的 `--dsw-specific-sidebar-nav-item-active` 画一个柔和高亮，未选中的一段透明，悬停时才出现一圈描边。实测 280px 宽的侧边栏：按钮 `x 141..201`、开关 `x 211..266`，间距 10px、垂直对齐；折叠成窄条时开关隐藏、按钮回到原位。

**启动时可见性的最终规则**：只有在"桌面端顶栏确实存在且宽度 < 200（窄条）"时才隐藏开关；没有顶栏（浏览器版）或顶栏还没排版好时，一律把开关画在标题栏那一格，绝不因为一次早期测量就什么都不画。测量循环改为"几何签名稳定 0.5 秒"才停，另有按帧合并的 DOM 观察器，顶栏出现/变宽/变窄都会立即重测（实测：先注入 56px 顶栏 → 开关隐藏；再放开成 280px → 开关下一帧落到顶栏、距折叠按钮 6px、垂直偏差 0px，全程没有派发 resize）。
**冷启动不显示开关的真正原因**：桌面端把开关画在 frame 级浮层里，位置来自 `chrome` 状态。首次挂载时，一个实例的副作用里先做了测量（发布 `present:true`），另一个实例那时还没订阅；而 `publish` 对"值没变"的发布不再通知，于是它永远停在初始快照 `{present:false}`——结果行内版已经隐藏、浮层版却没渲染，界面上什么都不剩，直到一次尺寸变化重新发布。修复是把"订阅后立刻取一次当前快照"（`adopt()`）写进 `useChrome`，并在每次重测的 tick 里也取一次。实测桌面渲染进程：加载 800ms / 3s / 8s 三次采样都是 `segments:2, inline:0, floating:1`，也就是恰好一个、在顶栏里。


## 已知限制

- 桌面端开关是一个浮层控件：它贴在折叠按钮左侧，但不属于侧边栏的布局流，所以侧边栏顶栏的拖拽区域里只有这一个非拖拽热区。
- 侧边栏折叠成窄条时开关整体隐藏：那时标题行会顶到窗口左上角，任何控件都会压住 macOS 的红绿灯按钮。展开后自动回来。
- 会话创建之后才注册的全局工具不会被屏蔽（预设仍然不让它碰代码）。
- 侧边栏过滤是"视觉隐藏"：被隐藏的行还在宿主的树里，键盘上下移动可能仍会经过它们；顶部的搜索也仍然搜全部会话，没有按模式缩小范围。
- 对话模式下的列表为了省掉缩进去掉了行首那格状态圆点，运行中状态在会话里看，列表里不再显示。
- 侧边栏标题和「新建对话」按钮依赖宿主的 `data-sidebar-workspace-header` 标记与 `dsw-icon-project-add-outline-regular` 图标 id；宿主改这两处时，替换会自动失效、退回原来的「工作区 + 添加工作区」按钮（不会出现空按钮）。
- 「写代码」回到最近一个不是对话工作区的工作区；没有这样的工作区时，沿用当前的默认选择。
- 对话模式不自带文件预览、终端、子代理、工作流等能力；需要这些能力就切回写代码模式。

引用修复：模型有时只写 `[3]` 而不写成 `[[3]](url)`。前端会在消息稳定后（400ms 防抖）扫正文文本，把裸 `[n]` 换成圆形徽标，链接取自这条消息自己的编号来源列表（位于该句之后、同一消息容器内、`li` 与链接数一致的最近一个列表）。**流式输出时来源列表写在正文之后**，所以早期一遍扫不到列表的段落不会被标记为"已处理"，列表出现后会再补上（之前就是因为提前打了标记，才出现"前半段没渲染、后半夜渲染了、刷新又正常"）。`code`/`pre`/链接内文本跳过；没有来源列表的文本原样保留。徽标 16px、间距 3px，两位/三位数字自动缩小字号不溢出。。

**多轮编号**：编号由模型自己"顺延"（提示词里写明：整个对话共用一套编号，新一轮新来源接着上次最大编号往下排，文末列表也用同一套编号）。前端不再替它重排，而是按**列表自己的起始编号**解析：`<ol start="13">` 就表示这一轮从 13 起。引用解析规则是"取包含该编号的那份来源列表"——先看本条消息后面的列表，再看更早的列表（近的优先），所以"引用上一轮搜索"也能指向正确的条目，且不受列表是否被虚拟滚动卸载影响。

**引用徽标的两种形态**：宿主既可能渲染成"文本为 `[12]` 的链接"，也可能渲染成"文本就是 `12` 的上标链接"。两种都会被打上徽标；因为上标链接自带 inline 的 `vertical-align:super` / 小字号，徽标用 `!important` 覆盖字号、垂直对齐、margin、尺寸，统一成 min-width 16px 的胶囊（两位数自动变宽）、baseline、左右 3px、`white-space:nowrap`，所以两位数不会再折成上下两行，所以两位数也不会压到前一个字。浅色主题下 `--dsw-alias-bg-layer-2` 本身接近白色，徽标额外加 0.5px 描边，白底也能看清圆圈（之前看起来像"悬空的蓝色小数字"）。

**对话表头的标签换字不换排版**：把「工作区」换成「对话」时，早期用的是 `font-size:0` + `::after` 重写文字，结果标签的 line box 从 20px 变成 25px、字形基线也和那一行的搜索/视图/新建按钮对不齐。现在改成：标签保留宿主自己的盒子与行高（14px / 20px），只把原字形设为透明，再在同一个 20px 盒子里用 flex 居中画出「对话」（颜色取 `--dsw-alias-label-tertiary`，与宿主标签同色）。实测两种模式下 header 36px、标签盒 20px、按钮 28px，三者中心都是 84，完全一致。
